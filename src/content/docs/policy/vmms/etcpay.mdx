## 개요

기타결제는 VMMS의 표기 내용으로, 유비씨엔에서 단독으로 제공하는 결제수단의 집합을 의미해요.
종류로는 `쿠폰`, `복지카드`, `멤버십 포인트`가 있으며, `QR(공통)`, `바코드(공통)`, `RF(복지카드만)` 방식을 통해 결제를 지원하고 있어요.
각 서비스는 독립적인 승인서버와 독립적인 전산 웹을 별도로 운영하고 있기 때문에 PG/VAN/전자결제사를 통한 결제와는 무관해요.

VMMS에서는 기타결제를 단순 수집데이터로 여기며, 언제든 사라질 수 있는 <strong className={"text-blue-600"}>시험적 제공</strong> 기능으로 표기하여 제공하고 있어요.

## 기타결제 서비스 종류

기타결제의 주요 서비스 종류는 다음과 같아요.

- 쿠폰
- 복지카드
- 멤버십 포인트

각 서비스는 서로 독립적인 승인서버와 독립적인 전산 웹을 운영하고 있어요.

## 처리 흐름

기타결제는 일반 카드 승인 거래와 처리 구조가 달라요.

1. 결제 요청이 발생하면 먼저 각 기타결제 서비스에서 `조회` 단계가 수행돼요.
2. 조회 결과를 바탕으로 각 승인서버에서 `승인` 또는 `거절` 처리가 이루어져요.
3. 정상적으로 `승인`된 경우에만 해당 결과가 온라인 서버를 통해 수집 개념으로 VMMS에 전달돼요.
4. VMMS는 각 기타결제 승인서버에서 승인한 최종 결과만 `기타결제` 항목으로 표기해요.

즉, VMMS는 기타결제의 승인 주체가 아니라 각 서비스에서 이미 처리된 승인 결과를 수집하여 보여주는 역할에 의의를 둬요.

## 표기 기준

- 기타결제 데이터는 `매입 대상`이 아니에요.
- `마감`, `매입`, `정산` 개념에 속하지 않아요.
- 오직 `수집` 개념으로 VMMS에 전달되고 표기돼요.
- VMMS는 정상 승인된 결과만 표기해요.

## 원거래 저장 원칙

- VMMS는 각 기관 법률에 따른 원거래 무결성 제약을 기준으로 동작해요.
- 단말기에서 올라온 원거래 정보만 승인하고 저장해요.
- 가공되거나 재계산된 정보는 저장하지 않아요.
- 따라서 금액 정보는 상품 구매 시 결제한 `최종 결제금액`을 기준으로 저장돼요.

## 운영 정책

기타결제는 서비스별로 독립적인 승인서버와 독립적인 전산 웹을 별도로 제공하고 있어요.
VMMS에서의 표기는 각 서비스 전산을 대체하기 위한 목적이 아니라, 통합 웹 표기를 위한 <strong className={"text-blue-600"}>시험적 제공</strong> 기능이자 운영 편의성을 위한 보조 표기 기능에 가까워요.

- 기타결제 서비스의 원본 데이터와 운영 기준은 각 독립 전산을 우선해요.
- VMMS는 편의성을 위해 최종 승인 결과를 보조적으로 보여주는 역할만 수행해요.
- 따라서 VMMS 표기는 각 서비스의 전체 업무 로직을 완전하게 대체하지 않아요.

## 연동 제한 기준

- 올바르지 않은 데이터가 누적되거나 쌓이는 경우
- 원거래 무결성을 해치는 형태의 데이터가 지속적으로 유입되는 경우
- 내부 감사 기준상 데이터 신뢰성이 유지되지 않는다고 판단되는 경우

위와 같은 상황에서는 시스템 내부 감사에 따라 기타결제 연동이 제한될 수 있어요.

## 서비스 중지 정책

기타결제는 독립적인 결제수단이기 때문에 서비스 품질과 신뢰성을 우선해 운영해요.

- 기타결제 서비스 오류가 발생하는 경우
- 정책 위반 사항이 발생하는 경우
- 추가 서비스의 증설 또는 축소로 인해 표기 이상이 발생하는 경우
- 표기 정확성 또는 안정성에 영향을 주는 문제가 확인되는 경우

위와 같은 상황에서는 서비스 신뢰성과 안정성을 위해 해당 시점을 기준으로 공지사항 안내 후 연동을 일시 중지할 수 있어요.

## VMMS에서 다루지 않는 범위

각 서비스는 별도의 서비스 로직을 독립적으로 운영할 수 있어요.
예를 들어 아래와 같은 기능은 VMMS의 관리 범위에 포함되지 않아요.

- 장바구니 결제
- 이벤트
- 할인
- 무상 제공

이와 같은 추가 서비스 로직은 각 서비스별 운영 영역에서 처리되며, VMMS는 해당 세부 로직을 다루지 않아요.
VMMS는 최종적으로 발생한 결제 또는 투출 결과를 표기하는 데 의미를 둬요.
