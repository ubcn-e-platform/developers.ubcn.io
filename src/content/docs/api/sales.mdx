<Frame>
단말기에서 발생한 매출의 거래내역을 조회할 수 있습니다.<br/>
거래내역은 승인·취소 건별로 결제수단, 카드/VAN/매입사 코드, 상품 정보, 매입·입금 예정일 등의 상세 정보를 제공합니다.<br/><br/>

<b>거래내역 조회는 `일 단위 전체 조회`와 `시간 구간 조회(최대 60분)` 두 가지 방식을 지원합니다.</b>

- 모든 요청은 헤더에 `company`, `token`이 필요합니다. ([API 시작하기](/api/) 참고)
- `GET`, `POST` 방식을 모두 지원하며, 요청 Body는 사용하지 않습니다.
- 조회 결과가 없는 경우 HTTP 상태코드 `404`와 함께 `salesList` 필드가 제외된 응답이 전달됩니다.
</Frame>

## 일일 거래내역 조회
<Frame>
    <strong style={"color: green"}>GET | POST</strong> /sales/`{date}`

    요청일자(`date`)에 발생한 거래내역 전체를 조회합니다.<br/>
    승인 건은 거래일자 기준, 취소 건은 취소일자 기준으로 포함됩니다.

    ### Request Schema
    요청에서 필요로 하는 필드는 다음과 같습니다.
    <Table headers={reqHeaders} bodys={[
        reqRow("date", "Y", "String", "조회일자 (Path)", "`YYYYMMDD` 규격<br/>오늘 이후의 일자는 요청 불가"),
    ]}></Table>

    ### 호출구문
    ```ts
    const API = axios.create({
      baseURL: `http://api.ubcn.co.kr/api`,
      headers: {
        "company": "{company}",
        "token": "{token}",
      },
      // 조회 결과가 없을 때 404가 응답되므로, 404는 정상 응답으로 처리합니다.
      validateStatus: (status) => status < 500,
    });

    // get, post 모두 지원합니다.
    // 예시) 2026년 10월 15일 하루 동안의 전체 거래내역 조회
    const res = await API.get("/sales/20261015");

    if (res.status === 200) {
      console.log(res.data.salesList);
    } else if (res.status === 404) {
      console.log("조회된 거래내역이 없습니다.");
    } else {
      // 요청 오류: code(존재하는 경우), message 를 확인합니다.
      console.error(res.data.code, res.data.message);
    }
    ```

## 시간 구간 거래내역 조회
<Frame>
    <strong style={"color: green"}>GET | POST</strong> /sales/`{date}`/`{time}`/`{minute}`

    요청일자(`date`)의 기준시간(`time`)으로부터 `minute`분 이전까지 발생한 거래내역을 조회합니다.<br/>
    조회 구간은 `(time - minute, time]` 입니다. (시작 시각 미포함, 기준시간 포함)<br/>
    실시간 연동을 위해 주기적으로 호출하는 경우, 이전 호출의 `time`을 다음 호출의 시작점으로 맞추면 누락 없이 조회할 수 있습니다.

    ### Request Schema
    요청에서 필요로 하는 필드는 다음과 같습니다.
    <Table headers={reqHeaders} bodys={[
        reqRow("date", "Y", "String", "조회일자 (Path)", "`YYYYMMDD` 규격<br/>오늘 이후의 일자는 요청 불가"),
        reqRow("time", "Y", "String", "기준시간 (Path)", "`HHMISS` 규격 (24시간제)<br/>`240000` 입력 시 `235959`로 처리"),
        reqRow("minute", "Y", "String", "조회 구간(분) (Path)", "기준시간으로부터 몇 분 전까지 조회할지 지정<br/>최대 `60`"),
    ]}></Table>

    ### 요청 제약사항
    - `minute`은 최대 `60`분까지 지정할 수 있습니다.
    - 조회 구간은 요청일자를 넘어갈 수 없습니다. (`time - minute`이 `000000`보다 작으면 요청 불가)
    - 당일 조회 시, `time`은 현재 시각 기준 **5분 이전**이어야 합니다. 단말기 거래 데이터의 수신 지연을 고려한 제약입니다.

    ### 호출구문
    ```ts
    // get, post 모두 지원합니다.
    // 예시) 2026년 10월 15일 14:00:00 기준, 30분 전(13:30:00 초과 ~ 14:00:00 이하)의 거래내역 조회
    const res = await API.get("/sales/20261015/140000/30");

    // 예시) 2026년 10월 15일 23:00:00 ~ 23:59:59 의 거래내역 조회
    const res2 = await API.get("/sales/20261015/240000/60");
    ```

    <b>※ 응답 규격 및 예시는 상단의 [일일 거래내역 조회]와 동일합니다.</b>
</Frame>

## 거래 데이터 해석 시 참고사항
<Frame>
    - **취소 거래**: 취소가 발생하면 원거래(승인, `payStep: 1`)와 별개로 취소 건(`payStep: 2`)이 취소일자 기준으로 추가 전달됩니다.
    취소 건의 `orgTransactionDate`, `orgTerminalTransSeq`, `orgApprovalNo`로 원거래를 확인할 수 있습니다.
    - **복수 상품 결제**: 한 번의 결제로 여러 상품을 구매한 경우, 동일한 `transactionNo`로 상품별 행이 나뉘어 전달되며 각 행의 `amount`는 해당 상품 금액입니다.
    - **입금 예정일 (주의)**: `payExpDate`는 영업일 기준으로 산정한 **순수한 예정일**이며, 입금일이 확정된 값이 아닙니다. 실제 입금일은 VAN사를 통해 입금 데이터가 전달되는 시점에 확정되므로 예정일과 다를 수 있습니다. 입금 여부·확정된 입금일은 [정산내역 요청](/api/adjust/)으로 확인해 주세요.
    - **매입 예정일**: `purchaseExpDate`도 영업일 기준으로 산정한 예정일이며, 실제 매입일과 다를 수 있습니다.
    - 응답 필드의 순서는 보장되지 않습니다. 필드명으로 값을 참조해 주세요.
</Frame>
