<Frame>
결제된 거래의 정산(매입·입금) 결과를 조회할 수 있습니다.<br/>
정산내역은 거래별 입금일, 수수료, 입금액, 매입일자 등 확정된 정산 정보를 제공합니다.<br/>
[거래내역 요청](/api/sales/)의 `purchaseExpDate`, `payExpDate`는 예정일이며, 확정된 정산 정보는 본 API를 이용해 주세요.<br/><br/>

<b>정산내역은 입금일 기준으로 조회하며, 한 페이지에 최대 `1,000건`씩 페이지 단위로 전달됩니다.</b>

- 모든 요청은 헤더에 `company`, `token`이 필요합니다. ([API 시작하기](/api/) 참고)
- `GET`, `POST` 방식을 모두 지원하며, 요청 Body는 사용하지 않습니다.
- 당일 정산내역은 **오후(12시 이후)에만** 조회할 수 있습니다.
</Frame>

## 조회 절차
<Frame>
    ### 왜 두 번에 나누어 조회하나요?
    정산내역은 거래 데이터와는 별도로 정산(매입·입금) 처리 결과가 반영되어 만들어지는 정보입니다.<br/>
    그래서 거래내역처럼 하루치를 한 번에 요청하지 않고, 안정적인 조회를 위해 **전체 건수 확인**과 **페이지별 조회** 두 단계로 나누어 조회합니다.

    | 단계 | 하는 일 | 호출하는 API |
    |------|---------|--------------|
    | 1단계 | 전체 건수를 확인하고, **몇 페이지를 조회해야 하는지** 계산합니다. | [정산내역 건수 조회](#정산내역-건수-조회) |
    | 2단계 | 1페이지부터 마지막 페이지까지 **페이지 번호를 바꿔가며** 정산내역을 받아옵니다. | [정산내역 조회](#정산내역-조회) |
</Frame>

## 정산내역 건수 조회
<Frame>
    <strong style={"color: green"}>GET | POST</strong> /adjust/pageinfo/`{date}`

    요청일자(`date`)의 정산내역 전체 건수와 페이징 정보를 조회합니다.<br/>
    조회해야 할 페이지 수는 `totalCnt ÷ pagingOffset`을 올림하여 계산합니다. (예: 2,500건 → 3페이지)

    ### Request Schema
    요청에서 필요로 하는 필드는 다음과 같습니다.
    <Table headers={reqHeaders} bodys={[
        reqRow("date", "Y", "String", "입금일자 (Path)", "`YYYYMMDD` 규격 (숫자만 허용)<br/>오늘 이후의 일자는 요청 불가<br/>당일은 오후에만 요청 가능"),
    ]}></Table>

    ### 호출구문
    ```ts
    const API = axios.create({
      baseURL: `http://api.ubcn.co.kr/api`,
      headers: {
        "company": "{company}",
        "token": "{token}",
      },
      // 조회 결과가 없을 때 404가 응답되므로, 404는 정상 응답으로 처리합니다.
      validateStatus: (status) => status < 500,
    });

    // get, post 모두 지원합니다.
    // 예시) 2026년 10월 15일 입금 기준 정산내역 건수 조회
    const res = await API.get("/adjust/pageinfo/20261015");
    console.log(res.data.totalCnt);
    ```
    <br/>

    ### Response Schema
    결과 값에 들어 있는 필드는 다음과 같습니다.
    <Table headers={headers} bodys={[
        row("type", "-", "Y", "String", "API 유형", "`adjust` 고정"),
        row("totalCnt", "-", "Y", "long", "전체 정산내역 건수", "-"),
        row("pagingOffset", "-", "Y", "int", "페이지당 건수", "`1000` 고정"),
        row("minRequestCnt", "-", "Y", "int", "요청 가능한 최소 페이지 번호", "`1` 고정"),
        row("maxRequestCnt", "-", "Y", "int", "요청 가능한 최대 페이지 번호", "마지막 페이지 번호는 `totalCnt`와 `pagingOffset`으로 계산하는 것을 권장합니다."),
    ]}></Table>

    ### Response JSON 예시
    아래 값은 이해를 돕기 위한 예시입니다. (HTTP 200)
    ```json
    {
      "type": "adjust",
      "totalCnt": 2500,
      "pagingOffset": 1000,
      "minRequestCnt": 1,
      "maxRequestCnt": 3
    }
    ```
</Frame>

## 정산내역 조회

        reqRow("no", "Y", "String", "페이지 번호 (Path)", "`1`부터 시작 (숫자만 허용)<br/>한 페이지당 최대 1,000건"),

    } else if (res.status === 404) {

    } else {
      // 요청 오류: code(존재하는 경우), message 를 확인합니다.
      console.error(res.data.code, res.data.message);
    }

## 정산 데이터 해석 시 참고사항
<Frame>
    - **입금일 기준 조회**: `date`는 거래일이 아닌 입금일(`payDate`) 기준입니다. 거래별 대략의 입금 시점은 [거래내역 요청](/api/sales/)의 `payExpDate`(입금 예정일)로 알 수 있으나, 이는 예정일일 뿐이며 실제 입금일은 VAN사를 통해 입금 데이터가 전달될 때 확정됩니다. 확정된 입금일은 본 API의 `payDate`로 확인해 주세요.
    - **환불**: 입금 이후 취소된 거래는 `adjustCode: 3`(환불)으로 전달되며, 요청일자가 평일인 경우 5영업일 전에 취소된 건이 포함됩니다. 이때 `tranDate`, `tranTime`은 취소일시입니다.
    - **당일 조회 제한**: 당일 일자로는 오후(서버 시각 12시 이후)에만 조회할 수 있으며, 오전에 호출하면 HTTP `403`이 응답됩니다.
    - 응답 필드의 순서는 보장되지 않습니다. 필드명으로 값을 참조해 주세요.
</Frame>
